VIII · 解读与下一步

这个原型证伪了什么、留下了什么

证实的部分
  • 规则即数据：11 份 markdown rule 各自独立 lint / version / 删除，引擎机械吃完。
  • forward chaining 真触发：r009 消费 r002 的 used_by_arc，r011 消费 r009 的 co_used_with 和 r007 的 shares_topic_with，trace 里有完整 parent 反向链。
  • 总体超线性：avg 19.2 derivations/rule。若 30 sources × 11 rules 是线性，期望 ~11 derivations，实测 211。
  • provenance 完整：每条 derived atom 都带 derived_from + parents，撤回一条规则 = 删 markdown + 重跑 = 它派生的全部消失。
证伪 / 限制的部分
  • 严格 L1.2 没过：r011 chain² 边际 = 2 < 5。原因不是引擎，是数据规模 + 链路设计 — r002 只产 5，r009 只产 2，r011 继承了上游稀疏。
  • r008 = 0：项目里没有重复 introduces_doc — 这其实是项目质量好；contradiction-lint 在没真矛盾的数据集上必然为 0。
  • r010 = 0：contributes_to 输出 6 条，但没有两条共享 topic — 30 sources 太稀疏。
  • "指数"二字得谨慎：在小数据集上真正放大效应的是 dense join (r007=152)，不是 chaining；要把 chain 放大到 dense，需要 (a) 50+ arcs，(b) chain rule 上游选 high-cardinality predicate。
下一步建议
  • 加 source 数：把所有 13 个 arc + 全部 docs 都吃进来（当前跳过了 5 个 arc 因为没有 9_summary）。
  • 设计 dense-chain rule：让 chain² 的上游是 r007 (152) 而不是 r009 (2)；例如 shares_topic_with + introduced_by → topic_neighbor_introduced_by。
  • 引入 LLM 作 extract layer：deterministic regex 抽出来的 atoms 偏 path-shaped；LLM 能抽 claim-shaped (e.g. "Difix3D shows pseudo-views help PSNR")，rule 的覆盖面立刻拉宽。
  • 把 wiki 接进 3dgs 主 docs/：当前是 sandbox demo；下一个 arc 把 atoms/rules 物化到 docs/wiki/，让真实任务流过引擎。
