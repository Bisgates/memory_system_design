Agent-native Zettelkasten

把 Luhmann 的卡片盒, 在 Lisp 的脑子里, 长成一个不被 1 万张卡片污染的 agent 长期记忆。
han · 2026-05-20

这份文档不是教 Luhmann, 也不是吹 Lisp。它是 arc 260520a 的下一步设计图 —— 上一轮 demo 跑出 211 条 derived atom + viz, 但 schema 反推审计指出: 我们押的是 graph join 能跑, 不是 内容能被读。25 条 query 里能稳健答 11 条, 缺的是 content / confidence / coverage / status 整组维度。这次我们把 schema 在那 8-dim 修订版基础上, 再叠 Luhmann 视角 + agent 视角, 给出一个能从今天的 demo 增量迁移过去的设计 —— 不推倒, 不 cargo-cult, 也不假装从零开始。

I · 处境

为什么这个问题, 是这个问题

先把 predicament 摆出来。agent 当下的记忆分两层。

短期记忆 = context window。 stateless。一次对话装多少, 关掉就清零, 下次重打。Claude 现在能塞 1M token, 但塞进去的不是"它知道的", 是"这次会话恰好有的"。会话结束, 这些信息从 agent 视角看 = 死。

长期记忆 = ……不存在。 现在所有声称是 "agent LTM" 的方案, 几乎都是 RAG 的搭便车: 把笔记切成 1k token chunk, embed, 余弦相似度召回 top-k。chunk 之间没结构, 召回完了塞 prompt, 用完丢掉。这个方案在 50 张文档时勉强工作, 在 1 万张时 retrieval 噪声等于内容。

naive idea → 致命缺陷

"那把所有笔记都喂给 agent 不就行了吗?" — context length 撑不住; "那 RAG 不就行了?" — RAG 是 flat bag-of-chunks, 没结构, scale 上不去; "那加个 knowledge graph?" — 经典 KG 是 schema-first, 维护成本超过收益, Cyc 失败 30 年了。

问题真正的难点是: agent 需要的是一个会自己长大的、有结构的、按需读取的、读完还能反过来写的记忆。读 ≠ search, 是 retrieval + 推理 cue; 写 ≠ append, 是 dedupe + consolidate。这四件事, 现有方案没有一个都干。

那为什么是 Luhmann

Niklas Luhmann 1960-90 年代用纸质卡片盒搞出 90,000 张卡片, 单人产出 70 本书 + 400 篇论文。他的 Zettelkasten 是已知最高效的人类外脑系统。它有四个 anchor:

  • 原子化 (atomicity) —— 一张卡, 一个想法。
  • 永久 ID (Folgezettel) —— 不靠目录, 卡之间用 ID 直接互指。
  • 用 link 不用 tag —— 类目是 emergent 的, 不预设。
  • 用自己的话 —— 复读不算笔记, 必须重新表述。

这四个 anchor 跟 agent LTM 的需求近乎一一对应 —— atomicity ↔ 不爆 context, link ↔ 关系是 first-class, emergent ↔ 不预设 schema, own-words ↔ agent 写回时也得是 representation 不是 copy。

但不能 cargo-cult

Luhmann 是 1960s 的个人思考工具。Folgezettel 数字-字母 ID (e.g. 21/3d7) 是因为他要在纸上用手翻; emergent hierarchy 是因为他没法 grep。agent 用这个系统, 必须保留原则, 不必保留形式。这份设计的工作就是把保留 / 修正 / 不适用三类逐条过一遍 —— 见 §III。

前序工作: arc 260520a 现在站在哪

上次 demo 的产出: 11 条规则 × 359 atoms → 211 derived atoms in 26ms。它证明 forward chaining 在 single-machine 上对 100s 级 atom 是 free lunch。但 schema 反推审计指出 25 条 query 里只稳健答 11 条 —— 全是 graph 形态, 缺的是 content / confidence / coverage / status / temporal / status 6 类。

本设计建立在 schema 反推那张 8-dim 修订表上, 再叠两层: (a) Luhmann 的 ID + literature/permanent 区分; (b) agent 视角的 provenance / status / writeback signature。目标是从 demo 增量演进, 不是从零开始。

II · 张力

六个不能两边都赢的对立

这个系统的所有设计决策, 都是这六对张力的取舍组合。先把它们摆开 —— 任何 "聪明 trick" 都得跟其中一对的让步对账。

T1 · capacity ⇆ precision
塞得多 vs 抽得准
每加一张卡, retrieval 噪声地板 +1 单位。Luhmann 90k 是个人记忆量级, 不是无限。我们必须有 prune / merge protocol, 不能只 append。
T2 · atomicity ⇆ context
切碎 vs 自足
切得越细, 一张卡越复用; 但越细, 单张卡越无法独立被理解, 越依赖邻居。这就是为什么 link 是 first-class —— 没有 link, atomicity 就是粉尘。
T3 · link richness ⇆ query cost
关系满 vs 查得快
link 越 typed, 子集提取越准; 但 link 类型越多, 图密度越大, walk 越慢。8 种 typed link 是经验上的 sweet spot, 不是 32 种, 也不是 1 种。
T4 · write speed ⇆ consolidation
立刻写 vs 沉淀写
online single-write 像在脑子里直接写硬盘 —— 永远不会有梳理。借鉴 hippocampus → cortex 的 sleep replay: append 是即时的, consolidate 是异步的。
T5 · emergent ⇆ aligned
个体涌现 vs 集体对齐
Luhmann 是单人, 概念自然 converge。多 agent 用同一个 wiki, 不 align 就是 babel —— 每个 agent 各自创造 alias。需要 canonical entity layer 但不需要全局 schema。
T6 · specificity ⇆ generality
"这次" vs "总是"
"depth alignment Spearman 0.99" 是 specific fact; "新的 metric 必须跨 dataset 验证" 是 general principle。两类卡必须共存且分得清, 否则 general 卡会被 specific 卡淹没。

"一个原则, 不告诉你它的反例, 就是 marketing。" 这份设计的自检

III · 原则

Luhmann 原则, 逐条过 agent 适配

Luhmann 的 6 条核心原则, 在 agent 语境下: 3 条保留, 2 条修正, 1 条不适用。

原则状态为什么 / 怎么改
原子化
one card = one idea		 保留 恰好就是 agent context-economy 的根本。一张卡的尺寸上限 ≈ "一个 paragraph 能 quote 出的有意义 unit" (~200-500 char body + meta)。
用 link 不用 tag
connection over category		 保留 + 强化 原版只有 "see also" 一种 link。agent 用必须 typed (supports / contradicts / extends / …, 见 §IV)。tag 作为 derived view 仍可存在, 但不是 source of truth。
用自己的话
rewrite, not copy		 保留 对 agent 同样有效 —— LLM 复制粘贴 = 没消化, retrieval 时是 dead weight。写回时强制 paraphrase。
Folgezettel ID
21/3d7 数字-字母 mix		 修正 形式不保留 (我们有 grep), 原则保留: ID 永久不变, 不携带类目语义, 一旦分配不变更。我们用 YYMMDDx-nnn (e.g. 260520a-007) —— 时间锚 + 顺序, 跟 arc ID 同形。
permanent vs literature note
两类卡分开盒		 修正 Luhmann 把 "原文摘录" 和 "我自己想法" 分两盒。Agent 版扩成三类: literature (来自外部源, paper / doc / code), permanent (agent 自己沉淀的概念), experiential (一次 task 的具体观察 / trace)。三类 retention policy 不同 (见 §VI)。
emergent hierarchy
no predefined taxonomy		 不适用 (作 source-of-truth) / 保留 (作 view) Luhmann 没法预设 hierarchy 因为他在纸上。agent 工程上必须有 index / cluster 加速 retrieval —— 但这些是 derived view, 不是 source of truth。卡片之间唯一权威的是 link, hierarchy 是 hop-2 cluster 的 visualisation。

对比现代实现, 它们各 cargo-cult 了什么

Obsidian / Logseq / Roam

保留: link-don't-tag, plain-text。
漏: link 不 typed; 没有 atomicity 约束 (一个 .md 几千字也行); 没有 retrieval-quality 概念; 不为 agent 写, 是 GUI 工具。

Tana / Anytype / Mem.ai

保留: 节点级原子化, supertag。
漏: 把 schema 锁死成 first-class, 退回 Cyc 的路子; agent API 是 RPC, 不是认知接口。

Heptabase

保留: card + whiteboard 的空间记忆。
漏: 完全为人类视觉设计, agent 看不到 layout 信号; 没有写回。

arc 260520a v1 demo

保留: 原子化, forward chaining, deterministic engine。
漏: content / confidence / coverage / status 6 维 (见 schema 反推审计); 单 link 类型, 单 atom 类型, 单 source-of-truth。

所以这份设计不是第十六个二流 Obsidian, 也不是 Cyc-mini。它的判定特征是: typed link + 三类卡 + 异步 consolidation + 三层 index。如果一个实现少了其中任意一项, 就掉回上面的某个分类。

IV · Lisp

Lisp 的落点 — 诚实评估

用户在 voice memo 里强调 "Lisp 的 mental model 做聪明的抽象"。这一节诚实回答: 哪儿 Lisp 真有用, 哪儿其实 Datalog 更合适。

Lisp 的 4 个 mental move

M1 · S-expression as data

"代码即数据" —— 卡片可以是 sexp, 既能被 read 又能被 eval。fit: 高。一张卡 (card :id ... :body "..." :links (...)) 同时是结构化数据 + 可被 macro 重写。

M2 · macro / quasi-quote

用 macro 做 query expansion (类似 PRF), 用 quasi-quote 做 template card。fit: 中。macro 比函数好的地方是在 read 时把 cue 重写成 query plan; 但 Datalog 的 rule 也能做。

M3 · condition / restart

检索失败不 throw, 而是恢复 + 提示 agent 改写 cue。fit: 高。retrieval 是 best-effort 操作, condition system 比 try/except 更适合"有几种 fallback"的场景。

M4 · lazy sequence

子集提取产 stream, agent 按 budget 取头部。fit: 中。Python 的 generator 也能做, 但 Lisp 的 lazy stream 更原生 —— 让 ranking 是 pull-based 而不是 push。

但 Datalog 在哪些维度更直接

Lisp 的强项是抽象 + 元编程, Datalog 的强项是声明式 join + fixpoint。这两件事 agent wiki 都需要, 但它们是不同层:

  • rule engine 层 (像 demo 里的 r001-r011) —— 用 Datalog (或 Datomic 的 datalog dialect) 比 Lisp 自己写 forward chaining 干净 100 倍。声明式 + monotone + fixpoint 是 Datalog 的原生设定, Lisp 要自己造。
  • 抽象层 (rule 怎么被生成 / 重写, agent 怎么编排 retrieval) —— Lisp 的 macro / condition / closure 是 first-class, Datalog 没有。
推荐

底层用 Datalog (或同等声明式 rule language) 做规则 + 派生, 这一层从 demo 已经存在; 上层用 Lisp / Clojure (实际上 Datomic 本来就是 Clojure 系) 做卡片表示 + query expansion + condition handling。卡片本身是 sexp, 这给我们 "code as data" + 可程序化的重写。Python (demo 现状) 在这套架构里只剩 glue —— 短期保留, 中期迁。

"Lisp is the only language with no chasm between 'I have this idea' and 'I can write it down.'" — Paul Graham, paraphrased

把 Lisp 用作装饰是错的

用户问 "Lisp 装饰 vs 真有用"。直说: 如果 Lisp 在你的系统里只是"卡片用 sexp 写而已", 那它就是装饰, 不如用 YAML/JSON。Lisp 真正赚到的地方是 macro / condition / lazy / sexp 这 4 件加起来产生 compound 收益 —— 见 §V 子集提取要用 macro 重写 cue, 见 §VII 写回要用 condition 系统处理 dedup conflict。少了这些, 就别用 Lisp。

V · 闭环

子集提取 + 指针读取 + 写回

整个系统的 lifecycle 是个 4-step 闭环:

  1. cue → subset · agent 拿到任务, 系统从 huge graph 中抽出相关子集。
  2. subset → action · agent 用子集做事; 子集里嵌指针, agent 按需深读。
  3. action → delta · agent 干完, 产出新卡 / 新 link / 修正旧卡的草稿。
  4. delta → graph · 异步 consolidation worker 把 delta dedupe / merge / 写回。

step 1 · 子集提取的三个候选方案 + 推荐

这是最关键的一步 —— 不爆 context 的保证就靠它。我比较了三个主流方案:

方案原理优势劣势 / 何时不灵
A · dense retrieval + 1-hop expand 对 cue embed, 取 top-k 卡, 再 1-hop 沿 link 扩展 实现简单; cold start 友好; 完全 stateless 1-hop 太短, 跨概念跳不过去; embedding 在 1 万卡时噪声大
B · Personalized PageRank (PPR) on typed graph 从 seed 卡出发, 按 link type 加权随机游走, PPR 分数排序 能跨 hop 聚合; typed link 自然加权; 数学上稳定 需要 graph 预计算, sparse 子图慢; 没有 content 信号
C · 混合 — HyDE + PPR + provenance prior LLM hypothesis 扩 cue → embed top-k → 在这些 seed 上跑 PPR → 用 evidence_count / utility 做 prior 加权 content + structure 同时用; 老卡老 utility 自然 boost; 抗稀释 实现复杂; 调参面大
第一性原则

子集 = 任务 cue 的因果闭包 —— 包含什么 = "不包含会让任务质量下降的卡片"。这不是 "top-k similar", 是 "minimum sufficient context"。推荐方案 C: 它把 content (HyDE-embed)、structure (PPR)、experience (provenance prior) 三路信号融合, 任一信号失灵都还有另两路兜底。

step 2 · 指针 over inline · token 经济

子集里不是每张卡都 inline 全文。三档:

  • L0 · header only · 只放 id + title + 一行 gist (≤ 80 char), 60-100 token / card. 用于 "知道它在那".
  • L1 · summary · header + body summary (~ 200 token / card). 用于 "可能要用到".
  • L2 · full · 整张卡含 source quote. 用于 "必读 / 已 follow 过指针".

子集默认输出 L1 卡 + L0 邻居; 邻居作为 pointer 让 agent 按需提到 L2。token 预算 first-class —— 系统暴露 (estimate-tokens subset) 给 agent, agent 自己决定深读哪几个指针。

step 3 · 写回 protocol (sleep-replay 风格)

这是用户最强调的一点: 不要 online single-write。借鉴海马 → 皮层的 consolidation:

  1. online · agent 干活时产出的 candidate cards / links 进 scratchpad namespace, 不进主图。打 confidence ≤ 0.6 标签。
  2. fast consolidation (~minutes) · task 结束后 worker 跑: dedup against existing (semantic + structural similarity), merge candidates。promote 到 permanent 或 experiential。
  3. slow consolidation (~hours / nightly) · 全图扫描: 找重复主题 cluster, propose merge / split; utility-low 卡片建议 archive。需要 human (han) confirm 才执行。
  4. provenance · 每张卡记 created_by: agent_id, derived_in_task: arc_id, last_used_at, used_count。

writeback conflict

多 agent 并发写时, 用 Lisp condition system 模式: conflict 是 condition, 不是 exception。三种 restart 策略:

  • :keep-both — 两条都留, 加 conflicts link, 让后续 reader 看到张力。
  • :supersede — 高 confidence + 新 timestamp 胜出, 老的标 :deprecated_by。
  • :defer-to-human — 进 review queue。
VI · 规模

不退化检索 — 1 万卡片之后

这是 han 最强调的红线。1 万张卡片注入后, 检索 quality 不能被这 1 万张污染。三件事撑住这个保证。

1 · 三层 index, 不是单一 vector store

层结构查询特性
L_sym · symbol tablecanonical entity → card_ids (hash map)O(1) 精确命中。"arc 260508b 的所有卡" 走这条。
L_vec · HNSW vector indexcard embedding, with namespace partition语义 fuzzy 命中。HyDE-cue → top-k。
L_graph · typed link graph(subj, pred, obj) edges + PPR precompute结构性扩展。"这卡有哪些 contradicts / extends"。

三层互为 backup —— 一层失灵 (e.g. embedding 漂移), 另两层兜底。1 万卡时, L_vec 单层 noise 必上升, 但 L_sym + L_graph 是结构化的, 不被 vector 漂移影响。

2 · 主动 prune / merge, 不是无限堆

每张卡有 utility = α·used_count + β·recency + γ·in_link_count − δ·age。每周 consolidation 跑:

  • utility 长期低于阈值 → 提议 archive (移入 cold storage, 不删, 但不进 default 子集提取)。
  • 高语义相似 + 高 link 重叠 → 提议 merge。
  • "垃圾稀释" 检测 — 一次性 dump 一大批卡时, 给这批卡打 quarantine 标签, 不进主图 retrieval 直到通过 utility 阈值。

3 · namespace + boundary cutoff

retrieval 默认在当前 task 的 namespace + 1-hop 邻居完成, 不扫全图。namespace 跨度: 3dgs/, quant/, life/, tars-meta/。跨 namespace 的卡片走 cross-pollination link, 这种 link 是 promote 出来的 (utility 高 + 多次被跨 ns 引用), 不是默认创建。

scaling 的具体承诺

10 张卡 → retrieval F1 ~0.9; 1k 卡 → ~0.85; 1 万卡 → 目标维持 0.75-0.8。掉点的部分会来自cross-namespace 任务, namespace-internal 任务掉点应该 ≤ 5%。一个差系统在 1 万卡时 F1 会掉到 0.4 (RAG 在 chunk 量上来后的实测水平)。

⚠ 0.75 / 0.4 这些具体数字是设计目标不是实测; ground truth 在我们实际跑 1 万卡之前没法确认。10 万卡量级 (Luhmann 个人极限) 是不是同一套机制还成立, 没人有公开数据。

VII · 落地

最小内核 + 从 arc 260520a 的迁移路径

遵循 "大系统先定 kernel + 列 unknown + 逐个 walk 通" 原则。

kernel — 5 个组件, 必须先在

K1 · card store

sexp-on-disk + symbol table。(card :id ... :body ... :links ...)。读写 O(1)。

K2 · typed link layer

8 种 link type (§frog 详述)。原 demo 的单 link 升级到 typed。

K3 · subset extractor

方案 C 简化版 (vector + 1-hop typed walk; PPR 先 mock); 暴露 (extract-subset cue budget).

K4 · writeback ingestor

scratchpad → fast consolidation; (append-card) + (propose-link); dedup by hash + cosine sim 阈值。

K5 · rule engine (复用 demo)

原 demo 的 forward chaining 整套保留; 只把 atom schema 换成新 12-dim。

park · 延后

多 agent merge / PPR / slow consolidation / cross-namespace link / quarantine / visual whiteboard —— 都先 mock 接口, 实现延后。

kernel 必须真能端到端跑通

端到端 = read 50 篇 3dgs paper 卡 → agent 用子集 reason → 产出 3 张新卡 + 5 个新 link → 写回 → 下次 query 能命中新卡。这是 demo 跑通后的下一个 acceptance bar。kernel ship 之前不加 feature。

migration path — 从 demo 增量演进

  1. step 1 · 给 atom 加 typed link 字段
    现在 atom 的 pred 是单层词汇表。改成 (link-type, target), 8 种 type。原有 11 条规则的 then 子句给每条边标 type。可单独验证: dedup + viz 颜色按 type 分。
  2. step 2 · 加 content_snippet + source_locator
    schema 反推审计的 R3 + R4。每张 atom 多带 200 char 原文片段 + (file, line_start, line_end)。验证: 任何 atom 能 quote 出原文。
  3. step 3 · 加 extraction_method + confidence
    R5。区分 regex / llm / hand, 0-1 confidence。LLM extract 路径开 (现在是纯 regex)。验证: 同一 doc regex 和 LLM 抽出来的 atom 都进, 不互相覆盖。
  4. step 4 · 三类卡 namespace 划分
    literature / permanent / experiential 三个 namespace 前缀。原 demo atom 都是 literature。新接口 (promote :from experiential :to permanent).
  5. step 5 · scratchpad + fast consolidation
    新建 worker (一个新组件, 不是改现有的)。先单测 dedup by hash, 再加 cosine sim 阈值。验证: 跑两次同样的 agent task, 第二次产出不重复。
  6. step 6 · 子集提取 v1 (vec + 1-hop)
    最简版的方案 C。HNSW + 1-hop typed walk。验证: query "depth alignment" 能取出 ≥ 5 张相关卡 + 8 个邻居指针, token < 2k.
  7. step 7 · utility 评分 + archive 候选
    utility 公式 + cold storage 入口。先只读, 不真删。验证: 跑 1 周 task 后, archive 候选列表 review 可信.
  8. step 8+ · park 列表的逐项
    PPR / multi-agent merge / cross-ns link / slow consolidation 按需求拉。

每一步都可单独验证, 都不破坏前一步, 而且都从 demo 现状出发。不推倒重做是核心约束 —— han 已经投了一晚上把 demo 跑出来。

afterword · principle to remember

当细节模糊时记住:

这个系统不是 KB, 不是 RAG, 不是 KG。它是 agent 的脑外脑: typed link 是它的突触, 三类卡是它的记忆分层, fast/slow consolidation 是它的睡眠, utility prune 是它的遗忘曲线。Luhmann 给了形态, 神经科学给了 dynamics, Lisp 给了 introspection。缺哪一个, 系统就会偏向已有的某个二流方案。

如果你只能记一件事 —— 记 §V 的 "subset = 任务 cue 的因果闭包"。这一句话决定了它跟 RAG 不一样的地方, 也决定了为什么这个系统能 scale 到 1 万张卡。

⚠ contested · 我没找到 PPR vs HyDE-混合在 wiki 子集 retrieval 上的直接 ablation; 学界做的多是 open-domain QA 上的对比, agent 长期记忆 corpus 上的实证缺。这部分推荐 (方案 C) 是论证选择, 不是实证选择。

In [md]:

;; agent 内部 (Lisp 风格 condition system)
(defun handle-task (cue subset)
  (let ((budget (subset-budget-remaining subset)))
    (loop for card in (subset-cards subset)
          do (case (card-relevance card cue)
               (:must-deep-read
                  ;; 拉 L2 (full body + source quote)
                  (when (> budget 800)
                    (let ((full (fetch-card (card-id card) :level :L2)))
                      (decf budget (token-cost full))
                      (collect full into deep))))
               (:summary-sufficient
                  ;; L1 已经在 subset 里, 不再拉
                  nil)
               (:irrelevant
                  ;; 标记 negative-feedback, consolidation 时降权
                  (mark-irrelevant (card-id card) cue))))
    ;; pointers — 按需 follow
    (loop for ptr in (subset-pointers subset)
          when (likely-needed? ptr cue)
            do (let ((c (fetch-card (ptr-id ptr) :level :L1)))
                 (decf budget (token-cost c))))))

In [10]: kernel.lisp (51 lines)
;; ============ kernel · 5 components, 51 lines ============
(defstruct card id ns type subj pred obj body links provenance status utility)

;; K1. card store — sexp on disk, symbol table in memory
(defparameter *cards* (make-hash-table :test 'equal))
(defun load-card (id) (gethash id *cards*))
(defun save-card (c)  (setf (gethash (card-id c) *cards*) c))

;; K2. typed link layer — link is a (type, target) pair on card
(defun outgoing (id type)
  (mapcar #'cdr (remove-if-not (lambda (l) (eq (car l) type))
                                (card-links (load-card id)))))

;; K3. subset extractor — vector seed + 1-hop typed walk
(defun extract-subset (cue budget)
  (let* ((seeds  (hnsw-topk (embed cue) :k 10))
         (walked (reduce #'union
                          (mapcar (lambda (s)
                                    (append (outgoing s 'supports)
                                            (outgoing s 'extends)
                                            (outgoing s 'contradicts)
                                            (outgoing s 'depends-on)))
                                  seeds)))
         (all    (union seeds walked))
         (ranked (sort all #'> :key #'card-utility))
         (subset (take-while-budget ranked budget))
         (ptrs   (subseq ranked (length subset)
                                  (min (+ 3 (length subset)) (length ranked)))))
    (list :subset subset :pointers ptrs :tokens (sum-tokens subset))))

;; K4. writeback ingestor — scratchpad → fast consolidation
(defparameter *scratchpad* '())
(defun propose-card (body links derived-in)
  (push (make-card :id (genid) :ns "scratchpad" :body body
                   :links links
                   :provenance `(:created-at ,(now) :derived-in ,derived-in
                                 :confidence 0.7))
        *scratchpad*))
(defun consolidate ()
  (dolist (c *scratchpad*)
    (let ((similar (hnsw-topk (embed (card-body c)) :k 3)))
      (if (and similar (> (cosine c (first similar)) 0.92))
          (merge-into (first similar) c)       ; dedup
          (progn (setf (card-ns c) "permanent")
                 (save-card c)))))
  (setf *scratchpad* '()))

;; K5. rule engine — reuse demo's forward chaining unchanged
(load "demo/engine.lisp")   ;; 11 rules, 2-iter fixpoint

;; ============ end-to-end one round ============
(defun one-round (cue)
  (let* ((sub (extract-subset cue 2000))
         (out (agent-reason cue sub)))     ;; LLM call, returns proposals
    (dolist (p (proposals out))
      (propose-card (proposal-body p)
                    (proposal-links p)
                    (current-arc-id)))
    (consolidate)))
