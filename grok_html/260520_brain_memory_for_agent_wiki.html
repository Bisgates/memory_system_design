记忆系统的设计学

大脑为什么不直接做"完美检索"——以及 agent LTM 应该从这个克制里学什么。

tars · learn_with_agent · 2026-05-20
I · The Predicament

Funes el memorioso, 或者一种地狱

博尔赫斯写过一个叫 Funes 的人, 落马之后, 他什么都不再忘。下午三点零四分一片云的形状, 他能完整复述; 一棵树上每片叶子的脉络, 他都能分别命名。他把每次见到的同一头狗都看作不同的对象, 因为光线变了、角度变了、毛的湿度变了——它**确实**不是同一头狗了。Funes 没有抽象, 也没有思考: 思考本来就是"忽略差异、把不同的东西捏成同一个"。一个不会遗忘的人, 也就不会概括, 不会推理, 不会决策。他被淹死在自己完美的记忆里。

这是关于记忆系统的第一个反直觉: "完美回忆"是 anti-feature 不是 feature。任何走进这个领域、想"为 agent 加上 long-term memory" 的工程师, 都会先想到一件事——能不能把所有 user message、所有工具调用、所有中间状态全部存下来, 然后做向量检索? 这就是 naive 答案。它的致命缺陷不是存储成本, 不是 latency, 而是它会让 agent 变成 Funes: 检索回来的东西太具体、太细、太相似, 反而无法支撑跨情境的归纳。

prior families: how does each dodge Funes

RAG (vector store)——靠 chunk 边界限制颗粒度, 靠 top-k 截断回忆量。Funes 问题被搁置, 不是解决: chunk 之间的语义混淆和 top-k 边界附近的"差一名召回失败"就是 Funes 的回声。

Conversation summarization——主动遗忘细节, 保留摘要。但摘要是哪种摘要? 这是个被回避的问题。

Symbolic / RDF wiki——预先规定哪些维度算"事实"。所有不在 schema 里的东西 silently dropped (han 的 arc 260520a 实际选了这条路)。这是最像大脑 declarative 系统的方案, 也是最承担"遗忘 = 设计"代价的方案。

大脑不是把"记忆"当作存储问题来解的, 而是当作预测问题来解的: 我以后**多大概率**还要用到这条信息, 用它来做什么 cue 启动的检索, 该用哪个时间尺度的子系统承载它。这个视角的转换是过去四十年记忆研究最重要的一次重排——从 1968 年 Atkinson-Shiffrin 的 sensory→STM→LTM 三盒模型, 走到现在的"多套并行子系统 + 不停 reorganize 的引擎", 教科书还在卖三盒模型, 但实验室不信它了。

"To think is to forget differences, to generalize, to abstract."Borges, "Funes the Memorious" 1942

II · Six Tensions

记忆系统的六个根本张力

一个记忆系统的设计, 不能同时优化所有指标——这是它跟 hash table 的根本差别。下面这六对张力, 每一对都是一条"你不能两头都要"的物理学约束。大脑用一套精巧的劳动分工把六对都吃下来了; agent LTM 现在大多只承认其中一两条。

tension一端另一端大脑的折中
① capacity vs precision存得多记得准STM 容量小 (Cowan ≈ 4 chunk) 但 high-fidelity; LTM 容量近无限但 lossy reconstruction
② encoding speed vs consolidation cost一次就刻进去慢慢压实海马快速 binding (秒级 LTP), 皮层慢慢吸收 (天-年)
③ interference vs separation类似经验合并每次都独立DG pattern separation 抗合并, CA3 pattern completion 抗碎片
④ generalization vs specificity抽出规则留住例外episodic 留例 (海马为主), semantic 留规则 (皮层为主), 之间是连续梯度
⑤ stability vs plasticity不被改写能被更新reconsolidation: 每次提取打开一个修改窗口, 然后再封
⑥ retrieval cost vs recall reliability想得起来不耗精力cue-driven 联想, 不是 brute-force scan; encoding specificity 决定能否命中

把这张表横着读: 大脑没有"一个 memory module", 它有多套并行的子系统, 每套在不同 trade-off 点上工作——declarative (海马依赖) / procedural (基底节 + 小脑) / 情绪强化 (杏仁核) / working memory (前额叶 + 顶叶分布式)。Cohen-Squire 1980 那个 declarative-procedural 划分, 至今是教科书上最 robust 的一条。

横着读的下一句是: 这些子系统不是被"内存层级"组织的, 而是被"信息生命周期"组织的。Atkinson-Shiffrin 的 sensory→STM→LTM 三盒模型 (1968) 是早期最大的误导——它暗示信息按时间从一个盒子流到下一个盒子, 然后 STM 是 LTM 的入口。这个图景到 1972 年 Baddeley-Hitch 的 working memory 模型就已经动摇了, 到现在被 Cowan 的 embedded-processes model (working memory 就是被注意力聚焦的那部分 LTM, 不是单独的盒) 进一步重写。盒子是错的比喻; 在线状态 vs 离线状态是对的比喻。

asymptotic check: 把哪条张力推到极限

把 ③ 推到极端 separation: 每个经验都独立, 没有 cross-link——就是 Funes。把 ③ 推到极端 completion: 一切都是同一团模糊——就是 dementia。健康记忆活在精确平衡上, 这个平衡点位于 DG (separation) 和 CA3 (completion) 的对接处, 是同一个海马回路里两个相邻 stage 的拉扯。

III · Encoding Stage

编码: LTP 与"指针式索引"

编码阶段要解的问题: 一段经验进来, 怎么用最少的"写入"留下足够多的 cue 留待后用? 大脑的答案分两层。底层是突触可塑性——Hebbian LTP/LTD, "neurons that fire together wire together"。Bliss-Lømo 1973 在兔子海马上首次记录到 LTP, 此后五十年, 这条机制从"现象"变成"settled 的细胞-分子级机制" (NMDA receptor → Ca²⁺ → AMPA receptor trafficking → 突触强化)。

上层是海马的 indexing 假说——Teyler & DiScenna 1986。他们的论点是: 海马不存内容, 海马存的是一个"指针", 指向当下被激活的那一组皮层 module。重放时, 海马这个指针重新激活同一组皮层 module, 你就"想起"了原始体验。这套假说三十多年了, 仍是主流——一个原因是它解释了为什么 H.M. (海马切除) 之后不能形成新的情景记忆, 但旧的语义知识仍在。

engram cell: 找到那条指针

Tonegawa 实验室 2012 年起的一系列论文 (Liu et al. 2012, Ramirez et al. 2013, Tonegawa et al. 2015) 把 indexing 假说推到了细胞分辨率: 用 light-activated channel 标记小鼠学习恐惧时 DG / CA3 / amygdala 里激活的特定 neurons, 然后**用光重新激活这群 neurons**, 小鼠就表现出"想起恐惧情境"的冻结反应——即使物理环境完全是新的。engram cell 假说由此从理论变成可操作的实体。

但这里有个仍未关闭的争论。engram 是地址簿 (sparse coding, 一小群专门细胞代表一段记忆) 还是全息图 (distributed coding, 整张网络的相位分布代表)? Tonegawa 风格的光遗传实验偏向地址簿——你能定位到具体细胞群。但 Stefano Fusi 一系的计算工作和最近的 high-density recording 数据偏向 mixed: 每个 engram cell 也参与无数其他 engram, "地址"和"全息"是同一现象在不同分辨率下的两种表述。

contested · 2026 现状engram 是 sparse 还是 distributed 不是非此即彼。当前主流是 "sparse 的功能 + distributed 的 substrate"——一小群 cells 是 readout 的关键节点, 但记忆的实际内容分布在更大的网络。这个"两层都对"的折中正在收敛, 但还没有形成统一术语。

pattern separation: 抗 Funes 的硬件

DG (dentate gyrus, 齿状回) 干一件非常具体的事: 把皮层送过来的高重叠输入稀疏化、正交化, 然后送给 CA3。皮层 layer II 大约百万级 neuron 投射到 DG 一千万级 granule cell, 但每次只有 1-2% 的 granule cell 激活——这种 sparse coding 的目标就是: 两次相似的经验, 即使皮层输入只差 5%, 送到 DG 之后的代码可以差 60%。Marr 1971 在他的海马 theory 论文里提了这一类机制的预测, 行为证据 (mouse touchscreen pattern separation tasks, Yassa & Stark 2011 综述) 和电生理证据都把它确认了。

CA3 干反向的事: pattern completion。CA3 内部有大量 recurrent collateral, 当你输入 partial cue, 网络的吸引子动力学会把它"补全"到原来的整个代码。retrieval 就是 completion 发动。

why this matters for agent LTM

DG/CA3 这套对接告诉你一件事: "encoding 时主动制造区分度"和"retrieval 时容忍 partial cue"是两个独立的能力, 必须分开建模。agent wiki 如果只做向量检索, 等于只有 CA3 (输入残缺 → 输出补全), 缺了 DG (输入相似 → 输出区分)。两个 atom 内容 95% 重合但本质不同 (e.g. 同地点的两次会议), 不主动加 "separation 钩子" 就会被合并查询淹没。

asymptotic lever: 把 encoding 推到一次性

大多数皮层 learning 需要重复; 海马支持一次性学习 (one-shot encoding)——这是它存在的理由。Hamming-style 极限检查: 把"重复"次数推到 1, 哪个子系统活下来? 答案是海马 + 杏仁核 (emotional gating, salience signal)。这反过来定义了海马的工作范围: 它处理 outlier、surprise、novelty——常态、重复的东西早晚要交给皮层。

IV · Consolidation Stage

巩固: replay, schema, 以及一场未决的辩论

编码完成不等于记住了。突触级的 LTP 维持几小时到几天, 之后会衰减——除非有巩固。Müller-Pilzecker 1900 年就观察到, 学习后干扰新学习能破坏旧学习, 提出了 consolidation 概念。一百二十多年过去, 我们对它仍有大段未解。

巩固分两层。突触巩固 (synaptic consolidation, 数小时, gene expression + protein synthesis) 这部分 settled——蛋白质合成抑制剂在学习后几小时内能阻断长时记忆形成, 这条因果链跑通了。系统巩固 (systems consolidation, 数周到数年, 海马依赖性逐渐转移到新皮层) 这部分**没有 settled**——它是脑科学过去三十年最持久的一场辩论。

standard model vs multiple-trace theory

Squire's standard model

新记忆需要海马"教学", 时间推移中海马反复 replay, 把模式刻进皮层。最终皮层网络能独立维持记忆, 海马不再被需要。证据: 早期 lesion 研究表明远期记忆相对不受海马损伤影响 (temporal gradient of retrograde amnesia, Scoville-Milner 1957 起)。

Nadel-Moscovitch's multiple-trace theory

每次提取一个情景记忆都会生成新的海马 trace, 因此 vivid 的情景细节永远依赖海马。海马只对褪色为语义 gist 的旧记忆"失去"依赖, 对仍有 vivid context 的记忆始终关键。证据: 高分辨率 fMRI 显示, 即使几十年的远期生动情景记忆, 海马仍然激活 (Bonnici et al. 2012)。

contested · 2025 进展2025 年 1 月 Neuron 上有一篇 review 直接以 "The post-standard-model age" 命名 (Sekeres, Moscovitch, Winocur), 把这场辩论的状态写成 "standard model 在 lesion 实验上仍有支持, multiple-trace 在 neuroimaging 上仍有支持, 两边都没法 falsify 对方"。一个新出现的方向是"trace transformation theory"——记忆既不是单向迁移到皮层, 也不是永远依赖海马, 而是随时间从 vivid episodic 形态转化为 schematic gist 形态, 两种形态在两个不同脑区同时存在。这是 2026 年最像"successor model"的候选, 但还没成共识。

replay: 离线重放的因果地位

清醒静息或慢波睡眠时, 海马 place cell 会以压缩时间 (10-20× 加速) 重新激活白天经验过的序列——sharp-wave ripple (SWR) 是它的电生理标记。这种现象 1989 年 Wilson-McNaughton 首次报道, 此后**现象**完全 settled, 但**功能**多次反转。

近五年最重要的实验进展: replay 不是均匀的, 它有偏向。被重放的不是随机的过去经验, 而是携带预测误差大的、有奖励意外的事件——dopamine signaling 直接调节哪些 sequence 被反复 replay (Mattar-Daw 2018, Liu et al. 2024 Nature)。这把 replay 从"被动 epiphenomenon"推到了"主动的优先级队列"——大脑在睡眠时不重放今天的全部, 它优先重放今天最 surprising 的那段。

replay 是 cause 还是 epiphenomenon

一系列 closed-loop 实验 (Girardeau et al. 2009 起, 2024 Liu et al. 综述) 通过实时探测 SWR 然后干扰它来测因果。结果: 干扰 SWR 选择性破坏空间记忆巩固, 不干扰则保留。这把 "replay 是 epiphenomenon" 这个 null hypothesis 推到了边缘。2026 共识: replay 有因果作用, 而且是 reward-prediction-error 引导的。这一条比 standard-vs-multiple-trace 那场更接近 settled。

schema: 不只是新数据进库, 是改库

Bartlett 1932 在 *Remembering* 里就指出: 记忆不是录像, 是重建——重建过程被 schema (背景知识结构) 强烈塑形。读一篇陌生文化的故事, 复述时人会无意识地把不符合自己 schema 的部分"修圆"。van Kesteren-Fernández 一系列工作 (2010s) 进一步: schema-congruent 信息绕过海马也能快速整合进皮层, schema-incongruent 信息严重依赖海马。schema 不是装饰, 它直接改变 consolidation 的速度和路径。

"睡眠重放今天最 surprising 的那段——优先压实失败和奖励意外, 这是大脑的 active learning。"

V · Retrieval Stage

检索: cue 驱动, 情境敏感, 重构性

提取一段记忆不是数据库查询。它有三个特征, 每一个都跟 SQL 想法相反, 每一个都是 agent LTM 当下做得最差的部分。

encoding specificity (Tulving)

Tulving-Thomson 1973 的encoding specificity principle: 一段记忆能否被提取, 取决于检索时的 cue 是否跟编码时的 context 重叠。在水下学的单词在水下记得更好, 喝酒时学的事醉了再想就更清晰 (state-dependent learning)。Godden-Baddeley 1975 那个潜水员实验是 textbook 案例, 至今 robust。

这里有个 Hamming-style 的推论: "我搜不到这段记忆"和"这段记忆不存在"是两回事。Tulving 的工作根本上挑战了"记忆 = 存了就能取"的简单观——存了不一定能取, 取的能力取决于你能不能复现编码时的 context。

retrieval-induced forgetting (Anderson)

Anderson-Spellman 1995, 1999: 反复提取一组项目里的某些, 会主动抑制同组未被提取的项目, 使后者更难想起。这不是 decay, 是active inhibition——前额叶通过 cortical pattern suppression 把竞争者按下去 (Wimber et al. 2015)。换句话说: retrieval 不只是 read, 它同时是 write——它在重写未来的可检索性。

cross-domain transfer: RIF 跟 reconsolidation 是同一件事的两面

每次提取打开一个修改窗口 (reconsolidation, Nader-Schafe-LeDoux 2000), 在这个窗口里, 被提取的轨迹增强, 没被提取的相关轨迹被抑制。这给"记忆 = 状态机"提供了一个具体机制——retrieval = state transition, 不只是 query。

reconstructive, 不是 retrieval

Bartlett 1932 的核心洞察被现代神经科学反复证实: 你"想起"一件事时, 你实际在做的是重新合成它。海马提供索引 + 时序骨架, 皮层提供细节填充, 你的当下情绪、当下 schema、当下意图全部参与塑形。每次"提取"都生成一个新的、与原始事件略有偏差的 trace——这正是 multiple-trace theory 在认知心理学侧的根。

结果: 记忆不应该被视为不可变记录。它是有"提取就会改变"性质的活体表征。法庭证词和目击者识别因此长期争议——重复审讯的过程本身污染了原始记忆。这也是为什么"心理治疗 + retrieval" (reconsolidation-based therapy) 能减弱创伤记忆: 在每次提取打开的修改窗口内, 引入新的安全信号, 改写记忆的情绪强度。

VI · Forgetting as Feature

遗忘不是 bug, 是 rational design

最反直觉的一章。如果"完美记忆 = Funes 地狱"是真的, 那遗忘的曲线就不是大脑设计的失败, 而是它的核心 feature。问题是: 大脑用什么原则决定哪些被遗忘?

Ebbinghaus 1885, 仍然 robust

Ebbinghaus 用自己当被试, 学无意义音节, 测保留率随时间衰减。他得到的遗忘曲线——前 1 小时陡降, 然后指数尾巴长达数月——在 declarative memory 上至今复现良好。但有个关键修正: 遗忘曲线只在 declarative 上成立, procedural 几乎不衰减。骑自行车、打字、滑雪, 这些技能一旦学会可以休眠几十年再启动。Cohen-Squire 1980 那条 declarative-procedural 分界, 在遗忘维度上有最锐利的体现。

decay vs interference: 一场没赢家的争论

decay theory

记忆痕迹随时间被动消解, 跟用不用无关。McGeoch 1932 起就有人反对, 但这条仍出现在直觉里。

interference theory

新学的东西 (retroactive) 或先学的东西 (proactive) 干扰目标记忆。Underwood 1957 的经典: 学完一长串单词, 之前学得越多, 这次记得越差——proactive interference 累积。这边证据更强, 但 decay 也没被完全推翻。

Anderson 的理性遗忘 (rational analysis)

John R. Anderson 1989-1991 提出 rational analysis of memory: 大脑遗忘的不是"用不到的", 而是预测下次用到概率低的。可提取性正比于"需要概率"。这个 framework 解释了为什么:

  • spacing effect——分散学习比集中学习记得久, 因为分散的 retrieval 暗示这条信息有持续需求。
  • testing effect——反复测试比反复阅读更牢, 因为 retrieval 本身是"我需要这条"的信号。
  • retrieval-induced forgetting——RIF 是大脑承认"这个 retrieval 路径上的竞争者用不到, 抑制掉"。

这条 framework 关键在于一个 reframe: 遗忘不是失败, 是 prediction 系统的正常输出。一条信息被忘, 是因为它的预测需求评分跌到了阈值以下。Bjork-Bjork 1992 的 "new theory of disuse" 进一步把"storage strength"和"retrieval strength"分开: 一条记忆可以 storage 很强但 retrieval 很弱 (一时想不起, 提示一下就来), 而 retrieval 弱本身可能是 feature——它在为未来更高效的检索腾出 cue 空间。

为什么 agent LTM 不应该用 LRU

LRU (least recently used) 是简化的 retrieval-strength 信号: 最近没用 → 评估为低需求 → 驱逐。但 Anderson 的 framework 暗示一个更强的策略: 用 base rate × recency × frequency × interaction-strength 综合估计 future need probability, 而不是只用 recency。spacing effect 的存在恰恰说明: 一条信息在分散时间点被访问, 比同样总频次但集中访问的, 应该被估为更持久。LRU 反着——它会把分散访问的项当作"半冷数据", 这是反过来的。

三条最值得抄的具体决策

(1) 把 consolidation 从 online 移到 batch。agent wiki 不应该在每次写入时都 re-derive 全图——这是 ACID database 的 mindset, 不是 brain mindset。大脑做的是: 白天用最简单的 binding 把新经验挂在海马 index 上, 晚上用 SWR replay 选择性把高价值经验整合进皮层 schema。工程对应: online 阶段只做 atomic extract + 写入 raw atom store; consolidation 作为 nightly / daily 跑的 batch job, 重新跑 forward chaining, 重新评估 schema integration, 重新计算 confidence/centrality。这正好跟 han 在 260520a 已经做的 fixpoint engine 兼容——只是把"每次写入立即跑"改成"积一批再跑"。

(2) retrieval = query expansion, 不只是 nearest neighbor。Tulving 的 encoding specificity 翻译成工程: 一个 raw query 的命中率严重依赖它跟 encoding 时 context 的重叠。所以 retrieval 阶段应该: (a) 用 LLM 把 query 扩展成多个 cue 变体 (hyDE-style), (b) 每个变体走不同的检索路径 (向量 + symbolic + temporal window), (c) 用召回结果再 re-rank。这等价于"模拟多 cue reinstatement"。

(3) forgetting 不是 LRU, 是 need-probability prediction。每个 atom 维护一个轻量 score: score = α·log(retrieval_count + 1) + β·log(referenced_by_atoms + 1) + γ·recency_decay(last_access) + δ·source_authority。score 低于阈值的 atom 进入 "deep storage" (依然可检索但不进 default candidate set); 进一步低于阈值的批量归档。这跟 Anderson rational forgetting 等价, 跟 spacing/testing effects 一致。

哪些机制不能直接抄: 形似神不似

don't copy this

(a) engram cell 的"地址簿"概念——你可能会想做"每条记忆 = 一个唯一 ID"。但大脑 engram 是 sparse-distributed 的, 同一群细胞参与多个 engram, 重叠是 feature。工程上你已经有 atom ID = sha1(s,p,o) 这种唯一映射, 不需要 mimic engram 的 distributed coding——你的 LLM embedding 已经替你做了 distributed 那一半。

(b) reconsolidation 的"提取打开窗口"——直觉会推你做"每次读取 atom 都允许它被改写"。这是 dangerous: 大脑的 reconsolidation 有几十种 molecular safeguard (protein synthesis 依赖、时间窗严格、特定 receptor 通路), 你没有任何对应的护栏。安全工程对应是: read-only 默认 + 显式的 "atom evolution" 操作 (新版本 vs 改写, 留 lineage)。

(c) "睡眠 replay 因此 agent 也需要睡眠"——形上对, 神不对。大脑睡眠 replay 服务的是 synaptic-level 稳定化, 这条对 LLM 不存在。但"周期性 offline 批处理"这个上层概念对 (=上面 (1) 的 batch consolidation)。区分: 借鉴 "batch consolidation"的功能定位, 不要借鉴"必须在 agent idle 时跑、必须时长压缩、必须 sharp-wave 频段"这些细节。

三个真正的 open question

(1) memory 是怎么"读出"的。我们知道编码、巩固的细节越来越多, 但提取的精确神经计算——cue 怎么变成 reactivation pattern, 哪些选项被同时唤起又被压制——仍然只有计算模型猜测, 没有直接观察。

(2) consolidation 的功能是"防止 catastrophic forgetting"还是"提取 gist"。两种解读都跟数据相容。complementary learning systems (McClelland-McNaughton-O'Reilly 1995) 把它建模成"海马 fast + 皮层 slow, 用 replay 把样本喂给皮层避免灾难遗忘"——这跟 deep learning 的 experience replay 直接同源。但近年很多数据更支持"consolidation = abstraction / gist extraction"——皮层吸收的不是细节, 是规律。两个解读对 agent LTM 的工程映射不同 (避免遗忘 vs 提取规则)。

(3) 个体差异为什么这么大。同样的 task, 不同人的记忆衰减曲线、巩固速度、易感性 (痴呆、PTSD) 差异巨大, 而我们对这种差异的机制还很模糊。这条对 agent LTM 暗示: 一刀切的 default policy 可能不足以服务不同任务密度的用户。

afterword · principle to remember when details fade

记忆不是存储, 是预测

大脑没把"完美回忆"作为目标。它把"我以后需要这条信息的概率有多大、用它做什么 cue 触发的检索"作为目标。所有的子系统——海马 indexing, 皮层 schema, replay 优先级队列, rational forgetting——都从这一个目标里 fall out。

当你为 agent 设计 LTM 时, 如果你只看"怎么把更多内容塞进去 + 怎么用 embedding 把它取出来", 你在做 Funes 的工程。如果你看"怎么预测哪些信息明天还有用、用什么 cue 才能 hit, 然后把这两件事变成系统的核心约束", 你在做大脑做的工程。这是借鉴的真正层级——不是抄机制, 是抄目标函数。

# pseudo-trace of what the brain does on cue "昨天那个谈话"
def recall(cue):
    # step 1: cue 进 prefrontal (working memory 控制)
    pfc.activate(cue)
    # step 2: pfc 派 query 给海马 (hippocampal index)
    candidates = hippocampus.partial_match(
        time_window="昨天",
        context_tag="谈话",
    )
    # step 3: 海马 retrieve 一个 sparse code, 这个 code 是
    # 当时被同时激活的那组 cortical modules 的 *指针*
    pointer = candidates.top()
    # step 4: pointer 重新激活原来那组 cortical modules
    # 视觉皮层 → "对方端着抹茶拿铁" 的画面
    # 听觉皮层 → "出租车喇叭" 的声音
    # 体感皮层 → "椅子有点硬" 的体感
    # 语义皮层 → 谈话的语言内容
    pattern = cortex.reactivate_from(pointer)
    # step 5: pfc 把 pattern 拼接成 *现在意识层面* 的回忆
    return pfc.reconstruct(pattern)

注意几个关键点:

(a) 海马没存"谈话内容"——它存的是一个稀疏指针, 指向当时哪些皮层 module 被同时点亮。这就是 Teyler-DiScenna 1986 的 hippocampal indexing 假说。

(b) 真正"回忆"是皮层被重新点亮——视觉、听觉、体感、语义皮层各回放各的, 海马只是 trigger。

(c) 你"想起"的不是录像, 是重建。每次重建都有偏差——你今天想到的"X 端的是抹茶拿铁", 也许其实是上周的另一次。这是 reconstructive memory, Bartlett 1932 起的核心论断。

stop & think

把这套机制跟 RAG 对比一下。RAG: query → embedding → 向量检索 → 返回原文 chunk。脑 retrieval: cue → PFC 控制 → 海马 partial match → 一个指针触发分布式皮层重建。

RAG 是"取出存好的字面"; 脑 retrieval 是"按指针重新跑一遍 forward pass"。这两件事的 cost / fidelity / fail mode 都不一样。RAG 永远不会"以为自己想起来其实想错了", 因为它没在重建——它只是在 read。大脑会, 因为它一直在重建。这给 agent wiki 的暗示: 检索后的 LLM 生成步骤其实是脑机制里"皮层重建"的工程对应——别把它当 bug。

[3] pattern separation: 怎么不混淆两次几乎相同的会议

In [md]:

okay 直接上具体例子。你这周在 cafe 跟 X 开了两次会, 都在角落, 都是下午, 都讨论 schema. 第一次主题是"反向工程 atom 维度", 第二次主题是"加 confidence 字段". 内容相似度 95%, context 也几乎一样。

问题: 一周后你想"上次跟 X 讨论 confidence 字段那次", 你的脑是怎么不把这两次混成同一段记忆的?

这就是 DG (dentate gyrus, 齿状回) 在编码时做的事。DG 把皮层送来的高度重叠输入稀疏化、正交化, 让两次相似经验在海马端的代码差异度远大于它们在皮层端的差异度。

In [3]:
# 简化版 DG 的 separation 行为
import numpy as np
np.random.seed(0)

# 两次会议的 cortical input: 95% 重合
input1 = np.random.binomial(1, 0.2, size=1000)
input2 = input1.copy()
flip = np.random.choice(1000, size=50, replace=False)  # 5% 不同
input2[flip] = 1 - input2[flip]
overlap_cortex = (input1 == input2).mean()

# DG 模拟: ~1% sparsity + 强非线性阈值
def dg_encode(x, W, k_winners=10):
    h = W @ x
    top = np.argsort(h)[-k_winners:]
    out = np.zeros_like(h)
    out[top] = 1
    return out

W = np.random.randn(1000, 1000) * 0.05  # DG granule cells
code1 = dg_encode(input1, W, k_winners=10)
code2 = dg_encode(input2, W, k_winners=10)
overlap_dg = (code1 * code2).sum() / 10  # IoU on active units

print(f"cortex input overlap: {overlap_cortex:.3f}")
print(f"DG code overlap     : {overlap_dg:.3f}")

[4] consolidation: why batch, why nightly

In [md]:

han 现在的 wiki 是 fixpoint engine——每次有新 atom 就跑一遍 forward chaining 直到不再有新派生。这是 ACID-database 思路: 写入立刻一致。

大脑不这样工作。大脑在白天只做最简单的 binding——海马快速给经验挂个 index。真正的 consolidation 在睡眠时发生——SWR (sharp-wave ripple) 期间, 海马以 10-20× 加速重放白天的序列, 把它们整合进皮层 schema。

这个分离是有原因的——不是"大脑慢所以分两步", 而是"online 期间不知道哪些经验值得记, 晚上有了完整一天的统计才能判断"。

In [4]:
# online 写入 vs offline consolidation 的本质区别
def online_consolidate(new_atom, store):
    """ACID 风格: 写入立即跑全图重派生"""
    store.append(new_atom)
    rerun_forward_chaining(store)  # O(|store|) every write
    return store

def offline_consolidate(new_atoms, store, schema):
    """脑式: 白天只 append, 晚上批 + 选择性强化"""
    # 白天阶段
    store.raw.extend(new_atoms)

    # 夜间阶段 (cron / scheduled job)
    # 1. 按 prediction-error 优先级选 replay candidates
    candidates = rank_by_surprise(new_atoms, schema)

    # 2. 选择性 chaining (不是全图, 是被选中的子图)
    derived = rerun_forward_chaining(candidates)

    # 3. schema integration: 哪些 derived 增强了 schema
    update_schema(schema, derived, congruent_only=True)

    # 4. 衰减: 哪些 old atoms 评分跌过阈值
    evict_low_score_atoms(store)
    return store, schema

为什么大脑用 prediction-error 引导 replay? 因为 prediction-error 是 "需要更新世界模型" 的最直接信号——预测对的事不用重学, 预测错的事是新信息。Liu et al. 2024 那篇 Nature 直接证明: 海马 SWR 优先重放奖励意外大的序列, dopamine 直接调控这个偏向。

这一条对 agent wiki 的暗示极强。consolidation 不是"把所有新 atom 都重新 chain 一遍", 是"把那些跟现有 schema 冲突 / 出乎意料 / 引入新 entity的 atom 重点 chain"。surprise 信号怎么定义? 看新 atom 跟现有 schema 的预测距离——一条新规则触发了 100 个 derive 而 schema 之前对应该 subgraph 是空的, 这就是大 surprise; 一条新 fact 完全可以从已有 rule 派生, surprise = 0。

[5] cue expansion: 搜不到的不一定不在

In [md]:

Tulving 1973 的 encoding specificity: 一段记忆能否被取出, 取决于 cue 跟编码时 context 的重叠。这条 49 年来一直 robust。

工程上的对应: raw query 的命中率严重依赖 query 跟 atom 编码时 context 的重叠。同一件事, 不同问法命中率天差地别。"那次讨论"vs "X 提到的 schema 反向工程"vs "上周关于维度审计的对话"——这三个 cue 在 atom 上的 hit rate 不一样, 即使指向同一个内容。

def multi_path_retrieve(query, store):
    variants = expand_cue(query, llm)
    results = []
    results += vector_search(variants["content"], store)
    results += symbolic_filter(variants["context"], store)  # provenance/temporal
    results += graph_walk(variants["semantic"], store)       # topic neighbors
    return rerank(results, original_query=query)

"搜不到 ≠ 不存在"在工程上等于: 检索失败时, 第一反应不是返回 empty, 而是 expand query 再试。这跟 hyDE (hypothetical document embeddings) 同源——HyDE 让 LLM 先编一个假想答案, 拿这个答案当查询。这正是"用一个更具体的 cue 模拟 encoding-time context"。

实际策略: 默认走 multi-path retrieve, 不要让 user 自己 craft query 变体。把 LLM 生成 cue 变体的 cost 摊到每次查询——这点 token 对 retrieval 质量的提升非常划算。

[6] forgetting: not LRU, but rational

In [md]:

han 的 wiki demo 现在没明确的遗忘 policy——atom 一旦写入永久留着。这是早期能 work 的简化, 但规模一上来会变成 Funes。需要 forgetting。

关键: 不要用 LRU。LRU 把"最近没用"等价于"低价值", 但 Anderson-Schooler 1991 的 rational analysis 给的更强信号是: 用 base-rate × recency × interaction-strength 综合估计 future need probability。

In [6]:
import math

def rational_need_prob(atom, t_now):
    """估计这条 atom 未来 24h 被需要的概率"""
    # 1. base rate: 这条 atom 历史上被 retrieve 的频次
    n = atom.retrieval_count
    base = math.log1p(n) / math.log1p(GLOBAL_MEAN_RETRIEVALS)

    # 2. recency: 最近一次访问的近邻性 (power-law 不是指数)
    dt = (t_now - atom.last_access).days + 0.5
    recency = 1.0 / (dt ** 0.5)   # Anderson-Schooler 用 power law

    # 3. interaction: 这条 atom 被多少其他 atom 引用 (graph centrality)
    cent = math.log1p(atom.referenced_by_count) / 5.0

    # 4. source authority bonus: 来自高权重 source (e.g. 1_objective)
    auth = 0.3 if atom.source_class == "core" else 0.0

    return 0.4 * base + 0.3 * recency + 0.2 * cent + 0.1 + auth

# 应用: 低于阈值的 atom 进入 "cold storage"
def consolidation_eviction(store, t_now, threshold=0.15):
    for atom in store.atoms:
        if rational_need_prob(atom, t_now) < threshold:
            atom.tier = "cold"  # 不进 default candidate set
    # 进一步低于二级阈值的批量归档

[7] a minimal brain-like LTM, evolving 260520a

# 三层 atom (左→右 越来越短期, 越来越富 context)
#
#  ┌──────────────────────────────────────────────┐
#  │  layer C: schema atoms                       │  <- 慢, 高权威, 跨 arc
#  │   (subj, pred, obj) + derived_from chain     │     "topic X has type Y" 等
#  │   ← consolidated nightly from layer B        │     ≈ 皮层 schema
#  ├──────────────────────────────────────────────┤
#  │  layer B: episodic atoms                     │  <- 中, 单 arc 内主导
#  │   (subj, pred, obj) + source span + ts       │     增加: span (file, offset), ts,
#  │   + separator (conversation_id / commit)     │     conversation_id, surprise score
#  │   + need_prob score                          │     ≈ 海马 index + replay queue
#  ├──────────────────────────────────────────────┤
#  │  layer A: raw spans (lazy hydration)         │  <- 最短期, content cue 走这里
#  │   (file, byte_offset_start, byte_offset_end) │     不是 atom, 是被 atom 指向的 token
#  │   + extracted_atom_ids                       │     ≈ 皮层 sensory trace
#  └──────────────────────────────────────────────┘
#
# 写入路径 (online, 快):
#   raw markdown → regex extract → write layer B atom
#                                + span 记录到 layer A
#
# Consolidation 路径 (offline, nightly):
#   1. 算 layer B 新 atom 的 surprise score
#      (相对 layer C schema 的 predict-error)
#   2. surprise top-k 走 forward chaining → 派生新 atom
#   3. 派生 atom 中 schema-congruent 的 → 上升到 layer C
#   4. layer B 中 need_prob < threshold → 迁 cold
#
# 检索路径:
#   query → LLM expand to multi-cue
#        ├─ content cue → vector over layer A spans → rehydrate via layer B
#        ├─ context cue → symbolic filter on layer B (ts, source, conv_id)
#        └─ semantic cue → graph walk on layer C schema
#   → rerank, return
In [md]:

这套草图的关键设计:

(a) 不动 260520a 的 RDF core——(subj, pred, obj) + derived_from + parents 这套保持。

(b) 加 layer A (span) 解决 content cue 缺失, 但不污染 atom——span 是按需 lazy load, atom 不背 free text。

(c) 加 layer B 的 separator key + surprise + need_prob——这三个字段直接让 pattern separation / replay 优先级 / rational forgetting 都 work。这是最大改动, 但都是 atom 的 metadata, 不改它的语义形状。

(d) layer C 是已有的 schema 衍生——但被 promote 进来的是 cross-arc / schema-congruent / 高 centrality 的 atom, 不是所有派生 atom 一视同仁。

(e) consolidation 改成 nightly batch——260520a 现在每次写入立即 fixpoint, 改成 batch 后写入路径变快, batch 时还能做 surprise-driven 选择性 chain。

lab · batch vs online consolidation under noise injection
此 lab 揭示: 两种 consolidation policy 在 noisy ingestion 下的 retrieval F1 差异 (对应 §4 + §7 设计选择)

stop & think

注意一个 anti-pattern——把 surprise-driven 推到极端会让你只保留异常而 underweight 常态。常态是 schema 的支柱, 不是噪声。Anderson rational forgetting 里 base-rate 那一项就是为了防止这个: 经常被 retrieve 的常态 atom 即使每次都低 surprise, 也保持高 score。

所以三件事必须同时存在: (1) surprise-driven consolidation 优先级, (2) base-rate × recency × centrality 的 need_prob 评分, (3) source authority floor (e.g. 1_objective.md 写的事不能 evict)。三条联合, 你才得到一个 rational 系统; 单独使用 surprise = 只记得意外, 单独使用 base-rate = 收敛到 schema 平均、丢失 long-tail。

final anti-pattern

最大的 anti-pattern: 把大脑当 database 抄。大脑不是 database——它没 ACID, 没事务边界, 没主索引, retrieval 就是 destructive operation, schema 一直在被使用过程中改写。如果你试图找"大脑的 schema 文件在哪", 你在问错的问题。

正确姿势: 大脑给你的不是数据结构, 是 trade-off 目标函数——预测未来需求, 牺牲 storage perfection 换 prediction relevance, 牺牲 retrieval determinism 换 cue flexibility。你抄的应该是这个目标函数的形状, 不是它的实现细节。
